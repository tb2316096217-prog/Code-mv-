# 自检清单：声音重叠、字/图碰撞、帧级对位

> 这份文档来自 2026-10 pilot《增值税机器》的真实事故：成片交付后肉眼/耳朵发现 **两句旁白叠 0.55s、两段配乐叠 0.37s、Σ39 与 +13 框相撞、NOTE 框压住排线、标点单独掉行**。
> 这些都不是"感觉"，都能在交付前用检查抓到。**顺序：自动脚本 → 抽帧人看 → 才交付。**

## 1. 声音重叠自检

### 1.1 自动：`check-cues.mjs`

```bash
node scripts/check-cues.mjs <project> [--warn-only] [--voice-overlap 0.30]
```

规则（默认）：

| 规则 | 判定 | 级别 |
|---|---|---|
| 旁白 × 旁白 | 用 `audio/stems/words.json` 的**语音窗口**（没有则用 stem 全长），重叠 > **0.30s** | FAIL |
| 音乐 × 音乐 | 重叠 > **0.05s**，且没有 cue 声明 `crossfade >= 重叠秒数` | FAIL |
| 氛围 × 氛围 | 同上 | FAIL |
| 音效 × 音效 | 只提示（章/撞击这类叠加是设计内的） | WARN |
| `start_sample` 与 `round(start×sr)` 不一致 | >1 样本 | FAIL |
| 旁白语音超出片长 | 语音结束 > duration | FAIL |

报告写到 `audio/timeline-check.json`。

**为什么用 words.json 而不是 stem 长度**：TTS stem 会带前后静音尾巴（pilot 里 v_l3a stem 2.12s，语音其实 1.62s 就完了）。只看 stem 长度会误判；只看语音窗口才准。
`words.json` 由 `core/tts/asr_check.py` 生成（`word_timestamps=True`），时间已减去 0.6s padding；`check-cues` 会把负的起点夹到 0。

**音乐交叉淡化必须显式声明**：两段音乐相邻时，写 `"crossfade": 0.4`（或 `"conform": {"crossfade": 0.4}`），且 `crossfade >= 实际重叠`。没有声明 = 两段直接相加 = 双倍能量，pilot 的 0.37s 就是这么来的。

### 1.2 人工：听三处

- **两句旁白之间**：必须听到 ≥0.3s 的气口；
- **两段配乐交界**：电平不能"鼓一下"（如果鼓，多半是重叠）；
- **章/撞击簇**：impact + stamp + paper_slap 可以叠，但要有轻重层次（章最重）。

### 1.3 修法

- 旁白重叠：把后一句起点后移，或把前一句缩短/拆句；**移动后必须重跑 `check-cues`**（pilot 的错误就是把 v_l3b 从 14.27 改到 14.0 却没核对前一句语音结束 14.55）。
- 音乐重叠：显式 crossfade，或让 cue 之间留 ≥0.2s、由一段静音/纸声过渡。
- 音效簇：最多 3 个同时；给不同 pan/音高/时间偏移（pilot 的 +13 三连就是 300/323/345 帧错峰）。

## 2. 字 / 图元碰撞自检

自动脚本查不了"看起来叠没叠"，必须在渲染帧上按清单看。

### 2.1 联系表必须包含的"碰撞高发时刻"

| 时刻 | 为什么 |
|---|---|
| 每镜开始后 **+0.2s** | 元素 draw-on 到一半，文字/线条容易互相穿过 |
| **逐字显现中段**（数字、标题、画注的 40–60%） | 数字会显示成 "3 − 2 = 1" 这种半截状态；如果刚好和其它图元重叠，交付帧会很难看 |
| **画注出现 / 消失 ±0.1s** | 注框压到绘图元素、或两个注框交叠 |
| **章落定后 0.2s** | 红章与标题栏网格线、状态文字叠在一起 |
| **整张图纸/拉远镜** | 长文本（GENERAL NOTES 列表）与标题栏、边框相撞 |

示例命令（30fps，帧号 = 秒×30）：

```bash
ffmpeg -i out/mv.mp4 -vf "select='eq(n\,60)+eq(n\,300)+eq(n\,420)+eq(n\,435)+eq(n\,450)+eq(n\,537)'" \
  -vsync 0 out/check/collision-%02d.jpg
```

### 2.2 逐帧看什么（按顺序）

1. **文字压文字**：画注/标题/数字/状态栏是否互相覆盖；
2. **文字压线**：文字是否压在排线、尺寸线、图框、表格线上（半透明注框尤其容易"线从字后面穿过去"）；
3. **标点孤行**：逐字换行是否把 `。，、` 落到行首/单独一行（pilot 的 NOTE/2 就是句号单独掉到第二行）；
4. **注框压图**：画注框是否盖住机器/排线/气泡编号（pilot 的 NOTE/3 压住批发模块底边）；
5. **章压线**：红章文字是否被标题栏行线穿过（盖章压线可接受，但字被线穿就别扭）；
6. **数字完整**：逐字显现结束时，标签是否完整（没有停在 "3 − 2 = 1"）。

### 2.3 落地规则（写 scene 时直接遵守）

- **画注位置不用硬编码**：按当前镜头把纸面可见区算出来，找一块**不与任何已绘制图元相交**的空矩形再放；放不下就缩字号/换行/换镜。
- **注框底要够实**：`rgba(12,28,62,0.55)` 会让背景排线透出来；用 ≥0.8 或实底，或者给文字加一圈描边/底色。
- **换行做避头尾**：标点不能出现在行首；"。" 必须粘在前一个字上；英文按词换行。
- **同类标注先定布局**：Σ、+13、尺寸数字这类同族元素建一个标注布局表（x/y 槽位），不要各自硬编码（pilot 的 Σ 从 2330 挪到 2200 就撞上了 +13）。
- **章的位置**：先确认目标行/栏，把章中心放在整行中央，别跨行线；或者故意压线但把行线在章区域内隐藏（ink buffer 思路）。
- **半透明框禁止压在排线上**：要么移开，要么把框做成不透明。
- **每镜末帧检查**：画完一镜，看这一镜的"最后一帧"和"关键帧中段"，不要只看起始构图。

### 2.4 为什么会漏（pilot 的教训）

- 定调只抽了 4 张样张（2.2 / 7.2 / 15.5 / 17.9s），**刚好没覆盖 10s 的 Σ 碰撞、14.0–15.0s 的 NOTE 碰撞**；
- 画注框是"屏幕固定 620px + 纸面硬编码坐标"，没有按镜头可见区做避让；
- Σ 的 x 是在 30fps 改帧号时手动挪的，没有重跑布局检查。
