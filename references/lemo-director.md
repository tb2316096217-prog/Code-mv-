# 导演法（Lemo-Opuscar 设计层 · 中文改编）

> 改编自 `lemo-opuscar/DIRECTOR.md`（Lemo-Opuscar，MIT）与 `AGENTS.md`。只保留与本技能相关的内容，并把工具/交付换成 code-mv + studio。
> 与哪份 `STYLE.md` 搭配：**先选风格**，再读 `references/styles/<slug>.md`；导演法管"怎么讲"，STYLE.md 管"长什么样"。

## 0. 总则

你是导演，不是技术演示。片子的评判顺序：**声音 → 节奏 → 镜头 → 导演（表演/调度/情绪弧）**。好看的帧只是起点。

设计层与审核层分工：

```
STYLE.md + 本文 = 长什么样、怎么讲
anti-ppt.md G1–G9 + DECISION-LIST = 有没有"发生"（门禁，不改设计）
```

## 1. 接 Brief（一次问清）

用户给风格 + 主题，其余由你定。**一次问完，之后不再问**。默认：

- 片长 **30–60 s**；超过 2–3 分钟成本翻倍，要提前告诉用户。
- 1920×1080 @ **24 fps**；若该风格 STYLE.md 指定了 fps（30/60 等），以 STYLE.md 为准。
- 画幅可换：竖屏 1080×1920（布局基于 `U.W/U.H`，不写死数字）。
- 配音/字幕用用户的语言；字幕烧进画面并导出 `.srt`。
- 响度 **−14 LUFS**（母带后测）。

只在方案变化时加问：

- **不要配音/字幕**：删掉对应步骤，在 TREATMENT 里写明。
- **用户自带录音/音色**：直接用，ASR 转写取词级时间。
- **用户自有素材**（logo、照片、档案影像、数据、扫描、CAD）：先问有没有；用户给的优先，STYLE.md 列的来源是后备。下载前告诉用户：从哪、取什么、什么许可（见 §12）。

## 2. 先找 Benchmark

写任何东西之前，给这个**风格 + 主题**找 1–2 部参考作品（电影、片头、游戏、广告）。写下：

- **学什么**：构图、节奏、镜头语法、颜色逻辑、配乐结构。
- **不学什么**：角色、设计、旋律、具体镜头、logo、字体。

Benchmark 对质量的提升大于下面任何规则。

## 3. 故事

- **一个主体、一个目标、一个转折**：人/物/想法想要什么，发生什么变化，结尾与开头不同。
- **前 3 秒有钩子**：不要先慢慢出 logo 再开始。
- **结尾要回响**：呼应开头、揭示尺度、或让角色第二次做对。
- **一个 native move**：只有这个媒介能做的一下（折叠变转场、墨晕开进下一场、字网格咔哒变 logo）。放在情绪峰值。**STYLE.md §8** 列了该媒介的母题动作，选一个或发明一个。
- **砍掉多余**：缩略图大小能读懂的一个 gag，胜过看不懂的三个。

## 4. 先写 TREATMENT（画之前）

写 `TREATMENT.md`，**在画任何东西之前、在读该风格 `DEMO.md` 或 demo 代码之前**（素材型风格先集素材，见 §1）。必须含：

1. **三个候选结构**（各几行：单一旅程 / 前后对比 / 倒计时 / 会翻转的清单…），写明选哪个、为什么。开头画面、结尾、配乐形状都从主题长出来；第一个想到的通常是该风格的陈词滥调。
2. **Logline 与弧线**：一句话，然后 setup → turn → ending。
3. **Benchmark**：学什么 / 不学什么（§2）。
4. **Shot list**：每镜的景别（wide/full/medium/close/insert）、角度、运镜（推/拉/横移/跟/升降/变焦）、时长、**以及为什么要这样拍**。
5. **Beat sheet**：逐秒。
6. **Cue map**：tempo、小节网格、每段配器、每个切点/关键动作/字幕落在哪一拍。
7. **声音设计表**：每段的 ambience bed、主要 foley、音乐状态。
8. **字幕与标题设计**：排版是风格的一部分（以 STYLE.md §4 为准）。

> 本技能的补充：TREATMENT 之后、写代码之前，还必须产出 **`DECISION-LIST.md`**（逐镜反 PPT 决策清单，模板见 `anti-ppt.md`），过审才能开工。

## 5. 证明"看起来对"

- **有角色**：画 model sheet（转面、3–4 个表情、2–3 个关键姿态、配色）+ 2 张风格帧。
- **无角色**：3 张风格帧，其中 1 张是签名镜头。
- 用**真实绘制代码**渲（`render.mjs --stills` / `--sheet`），不要用别的工具拼 mockup；自己先对照 STYLE.md 过了再拿给人看。
- **分镜**：用户要求时才做；做法是渲 6–9 个关键镜头拼一张 sheet（镜头号/景别/时长/台词），附 logline 和最没把握的地方，等批准。

## 6. 声音是一半

- **每个可见动作都有声音**：落地、翻页、切、滴、点击、布料。材质要对（纸/木/金属/墨/玻璃各有各的声）。
- **三层**：ambience（房间、风、雨、城市）、foley（贴动作）、music。对话与关键 foley 下压音乐。
- **至少两处真静音或近静音**，放在转折或情绪峰值之前；静音后的第一个声音是全片最重要的声音之一。
- **至少两次用声音做转场**：下一场的声音提前进（J-cut），或上一场的声音盖过切点（L-cut）。
- **避免通用"钢琴+弦乐"**；用 STYLE.md §7 声音调色板里的乐器。

> 本技能的执行方式：声音设计表 → `cues.json`（`backend` 选 ComfyUI 模型或 `native:proc`）→ studio 生成 → 混音/母带。帧级对位见 `audio-studio.md`。

## 7. 节奏：先有音乐网格

- **先写 cue map 再动画**。画面锁在网格上，程序检查每个 cue 是否对位。
- **快慢要变**：快慢交替，有一次明确的加速或减速，给观众一口呼吸（长镜头或停顿）。全片一个速度 = 失败。
- **一个动作、一个声音、一个切**，但不要每拍都切。留时间看。
- **按观众读字速度，不按秒表**：
  - 每条字幕至少停留 **1.8 s**，且不短于**语音时长 + 0.6 s**。
  - 文字动画进入后，再停留约（英文字母数 ÷ 15 + 1.5）s；中文（字数 ÷ 4.5 + 1.5）s。
  - 标题卡至少 **4 s**。
  - 失败/笑点要给够时间理解。
  - 快，是靠"一屏少几个字"，不是靠没读完就切。

## 8. 镜头：每一镜都有理由

- 至少 **4 种不同运镜** + 真实景别变化。2D 也有相机：推、拉、视差、变焦、画中画。
- **一个签名镜头**让人记住：一镜到底、尺度揭示、介质自己做的转场。
- **转场长在介质里**（翻页、刻线生长、墨扩散），统一成一种语法；避免默认淡入淡出和硬切。
- 关键时刻主体至少占画面高度 **1/3**，调度清楚、剪影可读。

## 9. 表演

- 每个有意义的动作都要 **anticipation → action → follow-through**。角色要变表情，不是滑过去。
- **运动连续**：代码骨架的每个姿态用关键帧和缓动混合，不要在 `if` 里硬切姿态（一帧的漫画式 pop 除外）。
- 大动作前先渲染动作测试 sheet（伸/举/跑/跪）。手持道具要**在两只手掌之间**；手交手从一只掌心插到另一只掌心；滚动距离 ÷ 半径 = 转角。
- 关键动作按 **0.2 s 步进**放大检查。
- 每个表情在最终尺寸下检查，尤其眉毛方向："担心"和"生气"只差一个翻转。

## 10. 我们见过最多的失败

- 主体太小、太远，或挤在画面边缘。
- 太暗看不清，或颜色压在同色上（红压红）。
- 字幕盖住主体。
- 笑点/失误太快看不懂。
- 转场里有黑帧。
- 定时效果（iris、zoom、跟拍）在相机移动后不跟主体。

## 11. 交付前自检

- 跑 review loop：联系表、关键动作 0.2 s 条、带声音完整看一遍。
- **一轮修复**：把 review 和下面检查发现的问题一次修完，再检查一次；之后用户的新意见算新一轮。
- **不是 demo**：TREATMENT 后读 `DEMO.md` 对比结构/开场/签名镜头/相机路径/配乐形状/结尾——六项里至少四项要不同；交付前把你的联系表与该风格的 `poster.jpg`（本地有则看）并排做最后检查。
- 配音：每句都能被 ASR 正确转写（中文短句听错一个字属正常：听，若没问题就让检查以模型听到的为准）。
- 响度约 **−14 LUFS**；无黑帧、无 NaN 帧；字幕同步且不挡关键动作。
- 声音设计表每一行都真的进了 mix。
- **不出现 LemoLab 署名**：`grep -rniE "lemo ?lab|opus 5\.5" <project>` 除 LICENSE/CREDITS 外应为空，并亲眼看完最后几秒。

**交付物**（项目文件夹内）：

- `<name>.mp4`（默认 24 fps，约 −14 LUFS）+ `poster.jpg`；
- `<name>.srt`（有旁白/对白/字幕时）；
- `TREATMENT.md`、`DECISION-LIST.md`；
- `CREDITS`：所有第三方资产（采样库、音乐、字体、图片、语音引擎）+ 来源 + 许可；
- 源码 + 一条命令可跑的 `build` 说明。

**告诉用户**：项目文件夹与成片位置；CREDITS 列了哪些第三方资产和许可；素材使用权由用户负责。

## 12. 版权红线

- 参考作品只学语法，不抄角色、设计、旋律、镜头、logo、字体设计。
- 没有用户授权，不出现真实作品/游戏/品牌/事件。用户提供的 logo、照片、影像也一样：用户说有使用权才用，否则画虚构替身。
- 部分 demo 是真实事件/角色的非官方粉丝片：保留风格，绝不把那些名字、标志、角色带进用户的片子。
