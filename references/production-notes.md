# 反 PPT 与制作经验（production-notes）

> 合并自原 `opuscar-studio/references/REUSABLE-EXPERIENCE.md`（2026-10-28 并入 code-mv；内容保留）。
> 来源：2026-10-27《时间差就是价值差》R1–R5 实战（105 s 完整版 + 53.2 s 竖屏快剪）。
> 用法：写 `TREATMENT.md` 前读 §1–§4；做声音读 §5–§6；交付前跑 §7 清单。

## 1. PPT 感的来源与判据

- **PPT 感 = 知识被排成页面**：标题 + 要点 + 图标 + 分页，画面只是文字的容器。
- **反判据（最有用的一条）**：关掉字幕和旁白，观众还能不能从画面看出“发生了什么、数字怎么变”？
  能 → 不是 PPT；只能靠字看懂 → 就是 PPT。
- **结构判据**：段与段之间是“翻页/换卡”，还是“同一主体的形态变化”。

## 2. 结构选择：连续形变优先

TREATMENT 必须写三个候选结构并选一个。经验默认：

| 结构 | 样子 | 何时用 |
|---|---|---|
| **A · 同一主体连续形变（默认）** | 沙粒 → 网格单元 → 枝芽 → 沙粒，一个世界、一台摄影机、没有硬切 | 概念递进、有“时间/过程”的题（复利、概率、物理、生长） |
| B · 章节卡片 | 三个独立章节各成一屏，用 UI 展开过渡 | 并列清单、操作步骤、工具盘点 |
| C · 分屏对照 | 左右两条线同屏对比 | 真正的对照（名义 vs 实际、before/after），但要保留至少一个强意象，别全缩成图表 |

- **转场即论证**：形态变化本身就是“为什么是这样”的论证；硬切 = 重置 = PPT 感。
- 本片选择记录在 `TREATMENT.md §1`：明确否掉 B，理由是“会变成三支 PPT，失去时间连续感”。

## 3. 概念 → 机制 → 读数（开工必填表）

每个知识点必须同时有三样：

1. **可操纵的物理量**（沙粒、格子、树枝、灰、光……）
2. **看得见的变化**（累积、复制、抽枝、剪枝、倒流……）
3. **可读出的读数**（数字、比例、数量，能从画面数出来/算出来）

本片实例：

| 概念 | 世界机制 | 读数 |
|---|---|---|
| 本金 100 | 上仓 100 颗沙粒，1 粒 = 1 元 | 数得出来 |
| 年化 8% | 每列比前一列多一格（×1.08） | 列高差 / HUD 8% |
| 复利 10 年 | 第 10 列整列亮起定格 | 216 |
| 30 年 | 第 10 列顶端抽枝，树冠铺满画面 | 1006 |
| 通胀 3% | 灰从外向内剪枝，金色核心留下 | 415 |
| 折现 | 树梢碎成沙、粒子倒流回沙漏、箭头反向 | 46 颗回到上仓 |
| 价值差 | 收在开场同一只沙漏（构图押韵） | 46 vs 100 |

构造顺序（不要反）：

1. 写一句**世界观 / 物性比喻**（例：“本金掉进时间里开始生长”）；
2. 先算数、再写画面：所有数字可复算，脚本里的矛盾（本片原稿 485 vs 415）在 treatment 就标出并修正；
3. 定世界规则与参数（时间尺度、守恒、单位）；
4. 画**形变链分镜**（每个镜头只允许一个主动运动）；
5. 最后写旁白与字幕——旁白是**世界解说词**，不是 PPT 备注。

## 4. 反 PPT 的硬规则 + 视觉冲击

硬规则：

- 一屏只允许：**一个大主体 + 一个主动运动 + 一个巨型数字 + 一句短话**；
- 段与段之间用**形态变换**，不用切页；
- 不用图标、项目符号、卡片列表、流程箭头；
- 留白是尺度，不是“没内容”；
- 全片只一种强调色；
- 每个数字必须能从画面复算。

视觉冲击来自**尺度跃迁**，不是装饰：

- 数量级差：4×4 小方块 → 满屏 11 列网格 → 树冠超出画面（相机 log 拉远）→ 剪掉一半 → 倒带回流；
- 满/空对比、构图押韵（结尾回到 0 s 的沙漏）、静音窗、光扫、单颗粒子的特写；
- 每个段落至少有一次“尺度或形态的跃迁”；不靠阴影、发光、贴纸制造冲击。

## 5. 节奏：长片 + 快剪双版本

- 先按完整叙事做 **90–120 s**；再为竖屏平台做 **45–60 s** 主版本。
- **不重做画面**：用 `cut-*.json` 时间 warp（anchors: new→old）压时长。
  本片 105 → 53.2 s：`[[0,0],[44,96],[53.2,105]]`，前 96 s 压进 44 s（约 2.18×），最后 9 s 放慢到 9.2 s 保标题可读。
- **旁白停顿上限**：≤ 2.5 s（本片从 4.6–10.4 s 压到最大 2.55 s；组内 0.3–1.5 s，组间 2–2.5 s）。
  拆短句但**不改一个字**；停顿上限要写进 `TREATMENT.md` 并被脚本/数据校验。
- **字幕**：快剪后合并相邻短句（同一批字，只在相接处加逗号），避免“读不完”；
  字幕窗 = max(语音时长 + 0.7 s，阅读时间 + 0.05 s)，且每条留 3.4 s 以上；`readcheck` 必须 0 不合格。
- **标题/关键标签**在 warp 中要留够可读时长：结尾放慢，不要全片匀速。
- **竖屏**：同一套 `render(t)` 代码按视口切两套布局与相机（重排，不是裁切）。

## 6. 声音：casting、一致性、配乐、电平

### Casting 与一致性

- 一次生成 4–7 个候选（VoiceDesign 文字描述 + CustomVoice 预置），每个候选给“同一句 + 全片 9 句 cast tape”，干声 + 带 bed 两版；**用户选定后才正式配**。
- 定稿后**不要逐句 VoiceDesign**（音色会漂）。用**第一句成品作 Qwen3-TTS Base Voice Clone 的 reference**（`ref_audio` + `ref_text`），全片同 seed。
  本片客观对比（对基准句的长期频谱相似度，越接近 1 越好）：逐句 VoiceDesign 0.83–0.89 → 统一 Clone 中位 **0.90**。
- **声音资产独立打包**，与片子版本解耦：
  `reference.wav` + `reference.txt` + `voice.json`（model/mode/seed/许可）+ `cue-template.json` + `samples/`（全部句子 + preview.mp3）+ `SHA256SUMS` + `README.md`。
- gen.py 的 clone 模式：cue 里写
  `voice: {mode: "clone", model: "Qwen/Qwen3-TTS-12Hz-1.7B-Base", ref_audio: "<绝对路径>", ref_text: "...", seed: 9002}`；
  工作流 `studio/comfy/workflows/qwen3tts_clone.json`。

### 背景音乐选型（踩过的坑）

- **先避雷音色**：金融/专业/严肃题材不要马林巴、玻璃音色、儿歌/轻科普音色——用户会直接说“不契合”。
- 可复用的 prompt 配方：**无鼓 + 钢琴/合成器 pad + 稳定脉冲 + 中性严肃 + 96 BPM 左右 + 小调**；
  例：`clean minimal corporate video music, muted piano chords, soft synth pad, steady pulse, neutral and serious, no drums, no vocals, 96 bpm, D minor, seamless`。
- 每次生成 **3–6 条 40–60 s 候选**；先用客观指标预筛，再让用户听 20 s 小样：
  频谱质心 200–500 Hz、4 s 窗 RMS 方差小、开头连续（无 20 s 空洞）、结尾有自然收束。
- 连续 bed 取代分段配乐后，原 SFX 可以保留；改时间轴时 SFX 重排、**MMAudio 必须在新画面上重生成**（条件于画面，不能只重排）。

### 电平与母带

- bed 比人声低 **10–15 dB**；用“旁白窗 RMS”“bed 空档 RMS”验收，不靠耳估。
- 连续 bed + 稀疏人声会带来高 crest：旁白可做 2:1 轻压缩（保留未压缩原声供复用），母带用
  `--target` + `--ln-tp 0` + `--lim` 组合，避免 limiter 把人声整体压回去。
- 每次混音后量旁白窗口 RMS；若母带里没人声，先查 `studio/audio/mix.py` 的 voice bus 是否并入 `mix_bus`
  （本项目 2026-10-27 修过这个 bug，R2 两版因此无声）。

## 7. QA 清单（全部可测量，缺一不可）

| 检查 | 阈值 / 要求 |
|---|---|
| `readcheck.mjs`（按成片视口/画幅跑） | 0 不合格；快剪/warp 后必须重跑 |
| 黑帧 `blackdetect` | 无 ≥0.2 s 黑帧 |
| 响度 / 真峰（ebur128 或 loudnorm 测量成片） | −14~−15 LUFS；真峰 ≤ −1.2 dBTP |
| 设计静音窗 | 数字零段 ≤ −100 dBFS；细正弦段 −43…−37 dBFS |
| 旁白存在性 | 旁白窗口 RMS 明显高于 bed 空档（10–15 dB） |
| ASR 回读（faster-whisper medium，阈值 0.92） | 记录近音差异清单，人工复核重点句 |
| 字幕 `.srt` | 与烧录字幕同文同时；16:9/竖屏各一版 |
| 版本治理 | 新版本号、旧文件不覆盖、每版 NOTES/CREDITS/build 脚本 |

## 8. 版本与可复现

- 每版新编号（r1…r5），旧版全部保留，绝不覆盖。
- 每版交付：成片 + 字幕 + 母带报告 + `R*-NOTES.md` + `CREDITS-r*` + `build-r*.sh`。
- 时间唯一源：`timeline.js` → `timeline.json`；改节奏先改数据/`cut-*.json`，再渲染，别在代码里散落魔法时间。
- 复利类数字先算好写进 treatment（100、216、1006、415、74、46 全部可复算）。

## 9. 下次开工顺序（照做即可）

1. Brief：主题/受众/风格/时长/画幅/语言/素材。
2. 写 TREATMENT：三个候选结构，默认选 A“连续形变”。
3. 填“概念 → 机制 → 读数”表；核对所有数字。
4. 定世界规则与形变链分镜（每镜一个主动运动 + 一次尺度跃迁）。
5. 先定旁白与字幕的节奏（停顿上限、字幕阅读下限），再生成声音。
6. Casting：4–7 候选 → 用户选定 → 第一句 clone reference → 打包声音资产。
7. 配乐：避雷音色 → 3–6 条候选 → 客观预筛 → 用户听小样。
8. 长片渲染 → 快剪 warp 版本（45–60 s，标题留速）→ 两版各自 QA。
9. 混音/母带按 §6 电平规则，逐项跑 §7 清单。
10. 交付并写 NOTES/CREDITS/build；旧文件保留。

## 10. 边界

- 这不是“套模板”：**知识 → 机制**的翻译、数字核对、镜头理由必须自己写；“AI 生成”不替代导演。
- 纯并列数据、访谈、操作教学、清单盘点类内容，章节卡片（B）或分屏（C）可能更合适。
- 时长不是越短越好：45–60 s 适合信息密度高的竖屏；有完整论证弧光时，保留 90–120 s 完整版。
- 声音/音乐“好不好听”只能由用户耳朵定；我们能做的是把电平、连续性、一致性、风格方向做到可测量、可解释。
